# Start Here — I Already Use AI

Use this path when the learner already has useful work in one or more AI products, local folders, cloud workspaces, notes, or automation tools.

## Start prompt

```text
Use the migration path in this repository to install my AI operating system. First verify that you can read README.md, START-MIGRATION.md, INSTALLER-MANIFEST.json, and the final checklist in INSTALLER.md. Then ask only the first migration interview question. Do not search, open, move, copy, rewrite, or summarize any archive until I approve the named source and purpose.
```

## Migration sequence

1. Verify the complete repository and the current AI's real capabilities.
2. Ask where existing AI work lives, recording locations only.
3. Ask which existing work the learner values and what currently fails.
4. Create a read-only inventory before proposing new architecture.
5. Classify existing material as:
   - current authority;
   - reusable IP;
   - historical evidence;
   - conflicting or ambiguous;
   - sensitive or credential-bearing;
   - obsolete but preserved.
6. Present a promotion proposal naming each source, destination, reason, provenance requirement, and approval need.
7. Copy only approved material. Never reorganize or delete the originals.
8. Convert provider-specific instructions into model-neutral controls where practical.
9. Complete the shared Phase 0 requirements work using confirmed current needs, not assumptions inherited from old material.
10. Continue through Phase 1 in `INSTALLER.md`.
11. Give each existing LLM the cross-LLM onboarding prompt below.
12. Run a clean-room test with an LLM that has no prior chat context.

## First migration interview question

**Where does your existing AI-related work live today? Name the products, projects, folders, or workspaces only. Do not paste sensitive content yet.**

## Cross-LLM onboarding prompt

```text
You are joining an existing AI operating system. Retrieve its machine-readable manifest, start-here document, requirements authority, archive boundary, capability rules, and current installation state before acting. Treat canonical files—not your chat memory—as current truth. Do not open archives unless the owner explicitly names the archive and purpose. Execute safe authorized work, ask only for irreducible facts or consequential approval, and record material changes with provenance and verification.
```

## Migration exit gate

Do not continue to Phase 1 until:

- existing locations are inventoried without changing them;
- current authority is separated from history and preference;
- sensitive sources have access rules;
- every promoted asset has approval and provenance;
- originals remain intact;
- current requirements are confirmed directly with the learner;
- provider-specific behavior has a model-neutral onboarding equivalent.
